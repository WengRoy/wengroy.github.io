迴圈工程年代：孵化 AI 應用不再手寫 Prompt，而是工程化整個迴圈

做 AI 應用的重心，已經從「怎麼把一句 prompt 寫好」轉移到「怎麼工程化整個 agent 迴圈（loop / harness）」——工具呼叫、記憶與 context 管理、自我修正、eval 回饋。2025 年 6 月，「context engineering」一詞正式取代「prompt engineering」成為業界共識。這一頁拆解：迴圈工程是什麼、六國怎麼把 agentic AI 推進政府、以及四大巨頭的原話。

① 多模態全機敏 ② 迴圈工程 ③ 高品味題庫自我驗測
🧠 五個你上台能講的技術重點

核心訊息一句話：「成敗不再取決於咒語寫得好不好，而是外殼（harness）工程做得穩不穩。」

概念 3：標準與框架——不用自己手刻迴圈
🔌
MCP（Model Context Protocol）

Anthropic 2024/11 開源的開放標準，被稱為 agentic AI 的「USB-C」。2025 年已被 OpenAI、Google、Microsoft 採用，12 月捐給 Linux 基金會旗下 Agentic AI Foundation。

🛠
OpenAI Responses API + Agents SDK

2025/3 推出，把工具呼叫、網頁搜尋、檔案搜尋、computer use、agent 協調（handoffs/guardrails）做成內建原語，開發者不用自己拼迴圈。

🕸
LangGraph

把 agent 建模成「有狀態、可循環的有向圖」，支援 loop/retry/reflect，專為「資訊在推理與工具間循環流動」設計。

🧩
推理模型 o1 / o3 的內在迴圈

OpenAI o1（2024/9）用強化學習訓練出「回答前先想」的長思維鏈，把「迴圈」內化進模型本身——給更多推論時間就答得更準。

概念 4：為什麼「不再手寫 Prompt」
當任務要跨多輪推理、跑數小時甚至數天，單靠一段手寫 prompt 根本撐不住——context window 會爆、狀態會漏、錯誤會累積。因此重心轉向工程化整個迴圈：用 compaction（壓縮）、結構化筆記（記憶）、工具最佳化、eval 回饋來維持長時任務品質。prompt 是「一句話」難以版控；harness 是「一套系統」，可寫測試、可量化、可持續迭代。 — Anthropic《Effective context engineering for AI agents》

🇹🇼 對台灣做政府 AI 的三個實戰啟示

1️⃣
賣的是「工作流」不是「一個超強模型」

別再幫機關找「最強的那個 AI 打雜」，而是設計「多工具、可自我修正、可長跑」的迴圈。價值在 harness，不在單一 prompt。

2️⃣
對標新加坡 GovTech

Pair／AIBots 已鋪到 4 萬公務員。台灣的政府 AI 平台（如 botrun）該把「共用底座 + agentic 工作流」當成產品定位，而非單點工具。

3️⃣
把 harness 的品質量化

迴圈的難處在 completion check、context rot、冪等工具、maker≠checker。這些必須有 eval 才能驗——正好接到三部曲第三頁「自我驗測」。
