🏗 模型正在商品化，Harness 才是護城河
「I don't prompt Claude anymore. I have loops running that prompt Claude and figuring out what to do.」 — Boris Cherny，Head of Claude Code, Anthropic（引自 Addy Osmani, Loop Engineering, 2026）
🎯 一句話總結 模型快速商品化（Claude Haiku / GPT-4o mini 等級已成 API 基準線）。Osmani：「設計 loop 比撰寫提示更難——兩人建造完全相同的 loop 可能得到完全相反的結果。」真正的護城河是 harness 的設計能力。
💣 四個必定壞掉的地方
Osmani 原文點名四個讓 loop 失效的根本原因，O'Reilly Radar 整理：「驗收責任、理解債務、工具安全、Maker vs Checker。」 — Addy Osmani + O'Reilly Radar
①

驗收責任仍在你身上

Loop 無人監督時也會無人監督地犯錯。Osmani：「你的工作是發布你確認能運作的程式碼（ship code you confirmed works）。」AI 說完成了 ≠ 真的完成了。

Karpathy 補充：AI 的 "jaggedness"（能力不均）——同一個 AI 展現博士水準的同時，可能在顯而易見的事上完全失敗。需要 checkpoint 擋住基礎錯誤複雜化。

✅ 解法 加入獨立的 Completion Check：執行測試、驗證 build、確認 side-effect 全發生。讓 CI 說完成，不讓 LLM 說完成。
②

Comprehension Debt（理解債務）

程式碼寫得越快，你對系統的認知落差越大。Loop 無人值守時累積的決策，你可能完全沒看過——下次要改的時候，才發現完全看不懂。

Osmani：「一人用它加速深度理解的工作，另一人用它迴避理解。Loop 不知道差異，你知道。」

✅ 解法 設 max_iterations 上限，超過就強制停，人工確認狀態。每輪 commit 留歷程，可回溯哪一輪開始走歪。
③

工具安全性（Token + 副作用）

給 AI 的工具太強、不可逆，token 使用模式可能「wildly vary」（Osmani 原文）。AI 在修 bug 途中可能誤刪資料、強推 main、打出真實 API 請求。

危險工具：git push --force、DROP TABLE、有 side-effect 的外部 API call。

✅ 解法 工具「少而精，且冪等」。多次執行結果相同才安全。破壞性工具不放進 Agent 工具箱，或加 dry-run 保護層。
④

Maker ≠ Checker

「寫程式的模型太容易給自己的功課打高分」（Osmani 原文）。同一個 Agent 既做事又驗收 = 讓學生改自己的考卷。Sub-agent 的核心價值在此。

Osmani：/goal 用不同模型判斷完成度，而非原製作 Agent——這是 loop 可以無人值守運行的前提。

✅ 解法 分離角色：.claude/agents/ 定義獨立的 Checker Agent，不共享 context。或讓 CI pipeline 當第三方驗證者。
🌳 版本控管整合：Worktrees 是護盾
Osmani 原文：Worktrees 通過 Git 隔離防止衝突——「兩個 agent 無法同時編輯相同檔案，這是 loop 能平行運行的基礎。」也是防止 Comprehension Debt 擴散到主分支的第一道護盾。 — Addy Osmani, Loop Engineering (addyosmani.com)
版本控管 + Agent Loop 四原則

🔒 主分支永遠可 deploy

Agent 只在 worktree / feature branch 工作。Osmani：「你的工作是發布你確認能運作的程式碼。」

git worktree add /tmp/task-1 -b feat/task-1

📋 每輪 commit，可回溯 Comprehension Debt

每個 Agent 回合做一次小 commit，git log 可回溯哪一輪開始走歪，diff 找出理解債務發生點。

🚦 PR Gate 是唯一的人工插入點

Checker Agent 通過後，開 PR 讓人工 review 再 merge。Osmani：這是你「保留工程理解」的最後防線。

🧹 失敗 Worktree 及時清理

累積太多失敗的 worktree 會搞亂 git workspace，同時清理也在清理 Comprehension Debt 的累積。

git worktree remove /tmp/task-1
🧠 Karpathy 心法：Manifest，不是 Instruct
Karpathy 提出用「manifest」（聲明意圖）取代「coding」——工作是聲明目標，讓 agent 自己決定路徑。LLMs 擅長朝著具體目標迭代，不要給指令，給成功標準，看它跑。失敗不一定是模型不行——「可能是人還沒找到對的指令方式」。 — Andrej Karpathy（整理自 The AI Corner / Insight Area）
🏁 進階篇的終極結論 Karpathy：「程式設計的瓶頸從實作速度，轉移到判斷力、任務分解、指令品質。」
Loop Engineering 不是在學怎麼寫 while loop——是在學如何設計一個系統讓 AI 安全地長期工作，然後你去彈吉他。
