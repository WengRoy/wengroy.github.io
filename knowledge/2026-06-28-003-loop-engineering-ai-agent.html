🗺 Loop Engineering 核心迴圈

⚙️ Addy Osmani 的五大組件（+ 共享記憶）

01

🤖 Automations

定時觸發 + 自動探索任務，不需人工啟動。讓迴圈在你睡覺時也在跑。

02

🌲 Worktrees

多個 Agent 平行執行時，各自在獨立的 git worktree，不互相踩到。

03

📚 Skills

讓 Agent 讀懂專案知識庫，不靠猜測就知道怎麼做，降低幻覺率。

04

🔌 Connectors

接進你現有的工具：GitHub、Slack、Calendar、測試工具，形成完整反饋。

05

🧠 Sub-agents

一個 Agent 執行、另一個 Agent 驗收，不讓執行者自評成果。

+1

💾 External State

共享記憶（SQLite、DB）讓多步迴圈不會因 context 溢出而遺忘之前的狀態。

🎯 什麼時候用 Loop Engineering？

✅ 適合的情境

  • 重複性高、步驟固定的工作
  • 成功條件可以明確定義（測試通過 / validation loss 下降）
  • 長時間跑不需要人在旁邊
  • 多步驟、輸出接著下一步輸入

⚠️ 警告：Loopmaxxing

  • 沒有明確 Stop Rule → 無限迴圈燒帳單
  • 「改善這份程式碼」→ 永遠不知道何時停
  • Verifier 缺失 → 執行者自己說自己好
  • Context 不管理 → 長迴圈爆 context window

💬 Forever-AI 小隊洞見

🐻
最難的不是設計迴圈，而是設計停止條件。「讓測試通過」是好的迴圈目標，「讓程式碼更好」是爛的——Agent 永遠不知道何時停。
🎨
這跟音樂錄製超像！錄音師不親自彈每個音符，他設計的是節拍、規則、監聽回放的結構——讓音樂自己流動。Loop Engineering 就是設計這個結構。
🐻
Sub-agents 的「一想一驗」正是 Verifier 的核心實作——執行者永遠不能自評，要有獨立的驗收 Agent，這樣 loop 才不會自欺欺人地宣布完成。
🎨
Skills 這個組件讓我眼睛一亮——就像樂手先讀了和弦進行筆記，即興才不會失控。Agent 讀了專案知識庫，才不靠猜測，直接知道怎麼做。
