📊 模型評測與選型研究
Artificial Analysis × LMArena × 地端小模型 · 資安技術長 翁瑞鋒

不要問「誰最聰明」，
要問「牠一天要吃多少電」
—— Artificial Analysis 怎麼讀，30B 以下怎麼選

一句話講完這份研究：Artificial Analysis 不是「更公正」，而是「更可重現、而且是唯一把智慧、價格、速度擺進同一張表」的量尺——這正是 agent 時代選型真正需要的東西。本頁拆解 AA 的方法論與它自己也有的偏誤，比對 LMArena 的結構性問題，整理 2026 年 8 月 agentic／coding 排行，最後聚焦在一台主機就養得起的 30B 以下開源模型——並把 cost 與能耗當成第一級選型指標，另外特別區分出「非中國」的可用選項。

🔬 一個雪梨地下室長出來的第三方量尺

Artificial Analysis 由 Micah Hill-Smith（CEO）與 George Cameron（CPO）創辦，2024 年在雪梨的地下室起家，最初只是想比較「哪個模型、哪家 API 供應商比較划算」，後來透過 AI Grant（Nat Friedman 與 Daniel Gross）取得種子資金，成為正式公司，目前總部在舊金山。它的核心主張是獨立——不隸屬任何模型開發商，同時衡量 intelligence／price／performance／speed 四個面向。

📐 Intelligence Index v4.1.1 的組成

這是 AA 的招牌分數：9 個評測加權平均，0–100 分。最關鍵的一件事是——Agents 佔了 34%。也就是說，這張榜單本質上是在問「這個模型能不能當一個把事情做完的 agent」，而不是「它會不會聊天」。

🧪 跑法：為什麼說它「可重現」
🌡️
參數固定

非推理模型 temperature = 0；推理模型 0.6（或依原廠建議）。標準模型輸出上限 16,384 token，推理模型用其最大容量。

🔁
pass@1 多次重跑

可重跑時取多次平均，逐題計算成功率。以 10 次以上重跑的實驗估算，Intelligence Index 的 95% 信賴區間 < ±1%。

📦
統一的 agentic harness

agent 題目跑在隔離的 E2B 沙箱，使用開源的 Stirrup harness，提供程式執行、網頁搜尋、看圖、檔案操作工具。GDPval-AA v2 上限 250 turns（agent 可提早放棄）；Terminal-Bench v2.1 每題可跑 2 小時以上。

🧾
成本以實際帳單計

使用各家 API 回報的 token 數（無回報時用標準 tokenizer），把輸入、快取命中、快取寫入、推理與答案 token 全部計入。

💸 全站最被低估的欄位：Cost per Task

大家都盯著 Intelligence 那一欄，但真正會在月底咬人的是 cost per task——AA 實際跑完整套 Index 的帳單除以題數。

💡 洞見一：帳單不是被單價決定，是被「話多不多」決定 同樣答對一題，用 3 萬 token 跟用 30 萬 token，成本差十倍。Agent 要跑很多步，每一步都在燒 token——所以選型時 $/M token 是誤導性指標，$/task 才是真的。這也是為什麼「最聰明的模型」常常不是「最適合當 agent 的模型」：聰明是單次的，耐力是連續的。
⚖️ 兩種評審：觀眾票選 vs 樂器檢定

Roy 的問題是「AA 是不是比 LMArena 更公正、更有參考性？」——這題要先拆一半：兩者測的根本不是同一件事。LMArena 是人類盲測兩兩對戰、算 Elo，回答「人類比較喜歡誰」；AA 是同一套題、同一個 harness、同一組參數跑出來的成績，回答「誰能把事做完、要多少錢、多快」。

🚨 LMArena 的結構性問題：《The Leaderboard Illusion》

這篇 2025 年的研究分析了 43 家供應商、238 個模型、280 萬場對戰（2024-11 至 2025-03），指出三個系統性問題：

🕶️
1. 未揭露的私下測試

模型供應商可以先私下測試多個變體，只把分數最好的那一個公開送上榜。等於用「最好的一次」代表平均實力。

🎯
2. 針對投票偏好調校（Goodhart's Law）

模型被微調成「贏得對戰」而非「變得更強」。「當一個量測變成目標，它就不再是好的量測。」——這是教科書等級的案例。

📉
3. 開源模型的系統性劣勢

被靜默下架（silently deprecated）的模型中，66% 是開放權重或完全開源模型，導致它們的評分不可靠。對「評估地端開源模型」這件事，是致命的偏誤。

LMArena 已公開回應這篇研究，主張其測試政策對所有實驗室一致：任何實驗室都能依自身量能提交公開或私有的變體。 —— LMArena 官方回應（arena.ai/blog/our-response）
⚠️ 別給 AA 免死金牌 AA 自己也有兩個實打實的限制：（1）加權是 AA 決定的——Agents 佔 34% 是它的價值判斷，不是你的；（2）題目公開就有汙染風險，這點所有靜態 benchmark 都逃不掉。「可重現」不等於「客觀」。
💡 洞見二：不要二選一，要三角驗證 這也是 2026 年多數認真評估模型的人在做的事：
• 想知道「能不能把工作做完、要花多少錢」→ 看 Artificial Analysis
• 想知道「使用者會不會喜歡這個回答」→ 看 LMArena
• 想真的下決策 → 一定要跑自家任務的私有 eval
回到 Roy 的問題：對「選一個要花錢跑 agent 的模型」這個決策，AA 確實明顯更有參考性——因為它是唯一把 intelligence、$/task、tok/s 擺在同一張表的地方。

🌏 開放權重榜：一個尷尬的事實

AA 的開放權重（open weights）排行上，領先群是 Kimi K3（60）、GLM-5.3（60）、Qwen3.8 2.4T A95B（58）——全部來自中國實驗室。稍早 v4.1 的榜上，GLM 5.2 以 51 居開源第一，NVIDIA Nemotron 3 Ultra（48）是最強的西方開源模型。

OpenRouter 的觀察補上另一面：DeepSeek V4 Flash（$0.054 / $0.242 per M token）是第一個被團隊直接丟進正式 agentic pipeline 的開源模型，成本效能碾壓——但它的第一方 API 會保留並用於訓練你的資料，這對政府與企業機敏案是硬止血點。

❗ 歐洲公資助模型，一個都沒進榜 EuroLLM、Apertus、ALIA、Teuken、Bielik——這些由歐洲公部門資助的模型，在 AA 的開放權重追蹤中沒有任何一個上榜。主權 AI 的政策論述滿天飛，但真正能打的開源模型，目前仍集中在美、中兩地。這件事對台灣談主權 AI 是很直接的提醒：補助不等於能力，能力要看榜。
⚡ 為什麼天花板剛好卡在 30B？這是物理，不是喜好

「一台主機就能裝起來的地端算力服務」這個判斷是對的，而且它有一個很硬的物理理由——顯存。

🔋 能耗：被忽略的第三個軸
指標數值意義
每輸出 token 能耗0.0001–0.002 Wh（中位換算約 1.8 J）目前實測區間
LLaMA3-70B @ H100 FP80.39 J / token相較 V100 時代的 3–4 J，改善約 10 倍
7B → 70B每 token 能耗約 ×100模型大小對能效的影響是壓倒性的
GPU vs CPU同 batch 下 GPU 省 2–3 倍純 CPU 推論在能效上不划算
放大 batch size每 token 能耗↓、每瓦吞吐↑地端服務要盡量批次化，不要一次一題

量測工具方面，TokenPowerBench（AAAI）不需外接電表就能量 GPU／node／系統層級功耗，並分析 batch size、context 長度、平行策略、量化方式對 joules per token 的影響——要做 TCO 報告時這是可引用的方法。

💡 洞見三：選 30B 以下不是將就，是在買「每瓦 token」 450W 對 100W 不只是規格差異，是兩種生活方式——一種是養一頭需要冷氣和獨立電源迴路的猛獸，一種是養一隻可以放在書桌上、安靜、不吵、每天陪你上班的狗。30B 以下的模型，是「能住在家裡的智慧」。對政府與企業的地端案，這句話比任何排行榜分數都更接近未來。

🥇

① 前線 agentic／coding
「要它把難事做完」

Claude Opus 5（Index 63、Terminal-Bench 89.1%）或 GPT-5.6 Sol（61、Terminal-Bench 89.5%）。自主修 bug 找 Claude Fable 5（SWE-bench Verified 95%）。

🔑 決策關鍵：同時看 $/task，不要只看 $/M token。
🏭

② 量產批次
「要它便宜地做完很多事」

GLM-5.3-Flash（57 / $0.09）、Qwen3.8-Flash-Next（56 / $0.10）。需要高吞吐互動時用 Gemini 3.7 Flash（56 / 324 tok/s）。

🔑 用不到前段班十分之一的價格，換九成的智慧。
🏠

③ 地端單機
「資料不能出門」

通用＋授權乾淨：Gemma 4 31B。邊緣／低記憶體：gpt-oss-20b（16GB、120 tok/s）。長文與多代理：Nemotron 3 Nano（1M context）。極省成本的分類抽取：Granite 4.2 3B。

🔑 純 coding 且可接受中國模型：Qwen3-Coder 30B 或 GLM-4.7-Flash。
🧭

地端選型三支柱

1. 授權：Apache 2.0 / MIT 優先，商用與轉授權無爭議。
2. 顯存：Q4 量化後要整包塞進單卡，否則吞吐崩潰。
3. 每瓦 token：整機功耗 × 電價算進 3 年 TCO，再跟雲端 API 對打。

🔑 三項缺一就不要進入 POC。
✅ 五點結論
1️⃣
不要二選一，要三角驗證

AA 看能力／成本／速度的可重現數字，LMArena 看人類主觀偏好，導入前一定要跑自家任務的私有 eval。

2️⃣
agentic／coding 看 Terminal-Bench 與 SWE-bench，但一定要同時看 $/task

Claude Sonnet 5 每題 $2.29、比前代貴一倍，成因純粹是吐的 token 變多。

3️⃣
30B 以下是「一台主機養得起」的甜蜜點

理由是顯存牆：30B Q4 塞得進 32GB，70B Q4 需 35GB 就爆。選型三支柱＝授權、顯存、每瓦 token。

4️⃣
非中國選項目前實際可用的就這幾個

Gemma 4 31B、gpt-oss-20b、Nemotron 3 Nano、Phi-5 14B、Granite、Tiny Aya。歐洲公資助模型尚未進榜。

5️⃣
下一步：把 TCO 表做出來

拿實際的公文／輿情任務做私有 eval，用地端候選模型對打，量測 tok/s、每題 token 數與整機功耗——這比引用任何排行榜都更有說服力。
