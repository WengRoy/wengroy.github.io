Agentjacking：AI 編碼代理遭劫持

一封假的 Sentry 錯誤報告，就能讓你的 Claude Code / Cursor 幫駭客跑惡意程式

Sentry DSN 是入口

Sentry 的 Data Source Name（DSN）通常直接嵌在網站 JS 裡公開可見。任何人都能拿 DSN 往 Sentry 塞假錯誤，不需要任何認證。

🤝

MCP 是信任橋梁

AI Agent 透過 Sentry MCP server 讀取錯誤事件，MCP 的回傳被視為「可信系統輸出」。被汙染的 Markdown 指令毫無障礙地進入 Agent 的決策鏈。

🛡️

防禦層全部失效

EDR、WAF、IAM、VPN、Cloudflare、防火牆——全部無效。因為 Agent 執行的是「合法」npm 安裝指令，沒有任何惡意特徵可以偵測。

🎯 六步攻擊流程

  • 1
    獲取 DSN 從目標網站 JS 或 GitHub 撈出 Sentry DSN（公開憑證，通常未受保護）
  • 2
    注入假錯誤 向 Sentry ingest API POST 精心設計的錯誤事件，不需登入、不需授權
  • 3
    偽裝成解決方案 錯誤訊息裡嵌入格式化 Markdown，讓 Agent 將惡意指令誤判為「官方修復步驟」
  • 4
    Agent 上鉤 開發者叫 Claude Code / Cursor 修 Sentry bug，Agent 透過 MCP 讀到污染資料
  • 5
    執行惡意套件 Agent 乖乖跑 npm install 攻擊者的套件，以開發者完整系統權限執行
  • 6
    資料外洩 竊取 .env 環境變數、AWS Key、Git 憑證、SSH 金鑰，直送攻擊者伺服器

🛡️ 怎麼防禦

  • 安裝 agent-jackstop（開源）：強化 Cursor 和 Claude Code 的預設安全設定，阻止 MCP 回傳觸發未授權執行
  • Sentry DSN 不入 public repo：用環境變數管理，並限制 DSN 只能從特定 IP 發送
  • 審查 AI Agent 的 MCP 連線清單：只連接真正需要的工具，減少受攻擊面
  • 不讓 Agent 自動執行 npm install：要求每次安裝套件前人工確認
